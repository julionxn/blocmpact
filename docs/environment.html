    Environment, camera and entities

    What surrounds the effect: fog, sky, celestial bodies, clouds and weather; shake, FOV and cutscenes; entity outlines and poses.

    11. Environment, camera and entities

    Environment (EnvironmentFx)

    It changes what Minecraft itself draws, so it works with any backend. Each value carries a weight from 0 to 1 that mixes vanilla with yours; several effects are applied in order.

    @Override public void environment(Frame f, EnvironmentFx env) {
    float k = FxMath.window(time(f.partial()), 0, 40, 160, 200);
    env.fogColor(0x302040, k).fogDistance(0, 64, k)          // atmospheric fog (biome/dimension)
       .skyColor(0x101020, k).starBrightness(1f, k)          // night in broad daylight
       .skyLightFactor(0.3f, k).ambientLight(0x202040, k)    // the world really gets darker
       .rain(1f, k).thunder(0.6f, k)                         // visual weather (this client only)
       .cloudHole(origin().x, origin().z, 60, 0.3f, seed());
}
    Group Methods
    Atmospheric fog fogColor, fogDistance, skyFogEnd, cloudFogEnd, waterFogColor, waterFogDistance
    Final fog (water, lava, blindness… included) fog(start, end, weight), fogFinalColor, fogSkyEnd, fogCloudEnd
    Sky skyColor, sunriseColor, sunAngle, moonAngle, starAngle, starBrightness
    Clouds cloudColor (alpha 0 hides them), cloudHeight, cloudHole(x, z, radius[, irregular, seed])
    World light skyLightColor, skyLightFactor, ambientLight, blockLightTint, nightVisionColor
    Weather rain, thunder
    Any attribute set(EnvironmentAttributes.X, value, weight)

    Camera (CameraFx)

    @Override public void camera(Frame f, CameraFx cam) {
    float since = since(IMPACT, f.partial());
    if (since >= 0) cam.shake(3f * (float) Math.exp(-4 * since));   // degrees
    cam.roll(2f * FxMath.wave(time(f.partial()) / 20f, 0.5f) - 1f).fovScale(1f - 0.1f * charge);
}

    shake (maximum), shakeFrequency, roll (add), rotate(yaw, pitch) (add), fovScale (multiply), fov (adds degrees), offset(Vec3) (add). It moves the real camera: it works without OpenGL and respects the player's shake setting.

    Cutscenes (Cinematics, Cutscene, Shot)

    @Override protected void onStart(TickContext ctx) {
    if (!isCaster()) return;                                   // decide who sees it
    Cinematics.play(Cutscene.builder()
        .time(this::time)                                      // follows the effect's clock (slow motion included)
        .focus(origin())
        .letterbox(0.12f, 0xFF000000)
        .shot(Shot.cut(0, 60, (c, k) -> CameraPose.lookAt(
            ShotContext.orbit(c.focus().add(0, 8, -16), c.focus(), ShotContext.l(k, 0, 120)), c.focus().add(0, 2, 0), 70f, 0)))
        .shot(Shot.sweep(60, 100, 10, (c, k) -> CameraPose.lookAt(c.focus().add(6, 1, 6), c.focus().add(0, 4, 0), 60f, 0)))
        .build());
}
    • A shot is a function (context, k) → CameraPose with k already eased (dolly). cut starts abruptly; sweep blends from the previous pose.
    • Write shots relative to the focus (focus, home, side, orbit, playerFeet), never in absolute coordinates.
    • Defaults: 5-tick fade in and 12-tick fade out, vanilla HUD and hand hidden, block collision, skippable (/blocmpactc skip or Cinematics.skip()), priority 0.
    • The player is drawn once the camera leaves their eyes, as in third person.
    • The cutscene camera does not inherit the walking sway (view bobbing): it fades out with the cutscene's weight. CameraFx shake and roll still apply.

    Entities (EntityFx)

    @Override public void entities(Frame f, EntityFx e) {
    Entity caster = anchorEntity(Minecraft.getInstance().level);
    if (caster == null) return;
    e.outline(caster, 0x66CCFF);                                                    // outline visible through walls
    e.pose(caster, EntityFx.RIGHT_ARM, PartPose.rotation(-2.6f, 0, 0).withWeight(k));   // arm raised to the sky
}

    Poses work with any model: parts are named as in its model tree (head, body, right_arm, left_arm, right_leg, left_leg, hat on humanoids; tail, etc. on others). PartPose supports rotation, offset (in model pixels), scale, visibility, SET or ADD mode and weight. Armor follows the parts.
