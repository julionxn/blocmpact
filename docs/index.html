    Blocmpact

    Blocmpact is a visual effects API for Minecraft 26.3 (Fabric, Java 25). It ships no effects and no style of its own: it gives you the pieces to build any effect (a hit, an aura, a weather event, a cutscene, an altered state, a diegetic HUD…) quickly and well. Every color, curve and shape is your call.

    1. What it offers

    An effect is a timeline with optional hooks, one per layer. Use only the layers you need.

    Layer What it does Works with Vulkan Where
    Level 0 · World Particles (vanilla or configurable), sound, emission shapes Yes TickContext.particles(), sounds()
    Level 1 · Interface HUD on a fixed-size canvas, markers anchored to the world Yes hud(HudContext)
    Level 2 · Geometry Meshes in the world through the official API: billboards, beams, rings, spheres, ribbons Yes geometry(GeometryContext)
    Level 3 · Screen Full-screen shader passes over the image, bloom, compositor, impact frames OpenGL only passes(...), screen(...)
    Environment Fog, sky, sun/moon/stars, clouds (color, height, holes), world light, rain and thunder Yes environment(...)
    Camera Shake, roll, FOV, offset; cutscenes made of shots Yes camera(...), Cinematics
    Entities Colored outline, part poses for any model Yes entities(...)
    Data All of the above from JSON with expressions, no compiling — assets/<ns>/blocmpact/effects/*.json

    Also: networking (one packet per effect, with a seed), server logic on the same clock, commands, hot reload with F3+T, accessibility settings and fault isolation (a broken effect or shader never takes the game down).

    2. Installation

    Players. Install Fabric Loader ≥ 0.19.5, Fabric API and Blocmpact. For level 3, set Options → Video → Graphics API → Prefer OpenGL. With Vulkan, effects keep working without their full-screen passes and the game says so once in chat.

    If a server mod launches Blocmpact effects, install it on the server and on every client.

    Developers. Declare the dependency from the Modrinth Maven:

    // your mod's build.gradle
repositories {
    maven { url = "https://api.modrinth.com/maven"; content { includeGroup "maven.modrinth" } }
}
dependencies { implementation "maven.modrinth:blocmpact:1.0.0+26.3" }

    // your mod's fabric.mod.json
"depends": { "blocmpact": ">=1.0.0" }

    To try an unreleased version: ./gradlew publishToMavenLocal in the Blocmpact project (JAVA_HOME = JDK 25), mavenLocal() in your repositories and implementation "me.julionxn:blocmpact:1.0.0+26.3".

    Gradle and Loom also need JDK 25 to run (Settings → Gradle → Gradle JVM in IntelliJ).

    3. Key concepts

    • Type and instance. A type (mymod:explosion) is registered once; every launch creates an instance with its own id, anchor, seed, speed and parameters.
    • Anchor (Anchor). Where the effect lives: a fixed point or an entity it follows (feet, center or eyes, plus an offset).
    • Parameters (FxParams). Named values that travel with the effect: numbers, booleans, strings and vectors. Colors are accepted as "#RRGGBB", "#AARRGGBB", a 0xAARRGGBB number or a 0–1 vector.
    • Seed. All variation comes from it: random(tick), hash(i), seedF() in shaders. Two players see exactly the same thing. Never use Math.random().
    • Clock with speed (FxClock). It advances by speed per tick. At 0.5 everything plays in slow motion on server and client without touching any constant; at 0 it freezes (pause). The speed can change while the effect runs (h.speed(...)) without any jump in the image. onTick(ctx, t) receives whole ticks; time(partial) gives continuous time for drawing.
    • Ticks and frames. Particles, sounds and state changes go in onTick. Everything that is drawn (passes, compositor, geometry, HUD, environment, camera) goes in the per-frame hooks and is computed from time(partial).
    • Camera-relative. Positions sent to shaders and meshes are subtracted from the camera in double (frame.rel(...), u.world(...)), so nothing jitters millions of blocks away. The eye is always at the origin, view bobbing included: shader rays start at vec3(0.0), and geometry, passes and HUD stay aligned while the player walks.
    • Range. range() (512 by default): beyond that radius the per-frame hooks are not called and the effect costs nothing.
